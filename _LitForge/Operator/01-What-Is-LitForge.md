# What Is LitForge

LitForge is an **Obsidian-native WriterOps system**. It is not “AI writes your book.”
It is a disciplined pipeline that helps writers move from idea → draft → ruthless review → fixes → ship.

## The promise

LitForge helps you:
- **Start** (when you have an idea but no structure)
- **Improve repeatably** (revision that actually makes the work better)
- **Prevent drift** (changes don’t silently break earlier decisions)
- **Ship** (a finished artifact + optional handoff packet)

## The canonical backbone

Every project can run a single canonical backbone:

**Discover → Position → Outline → Draft → Red-Team → Patch → Repeat → Ship**

You can run fast loops or strict loops, but the stages stay the same.

## What LitForge does *not* do

- It does not require you to generate drafts inside the vault.
- It does not promise “zero AI” or “AI-proof originality.”
- It does not replace taste, judgment, or responsibility.

## The moat

LitForge’s moat is **hostile review + diff-first fixes + regression checks**:
- Review is severity-graded and adversarial (by design).
- Patches are explicit, localized, and testable.
- Regression checks prevent “fixing one thing, breaking three.”

## Who it’s for

LitForge fits:
- Fanfic writers who want canon/continuity control
- Novel / webnovel writers who want consistent shipping cadence
- Nonfiction writers who need sourcing and claims discipline
- YouTube/script writers who want repeatable clarity and structure

If you want a “one prompt, generate a whole manuscript” tool, LitForge is intentionally not that.
